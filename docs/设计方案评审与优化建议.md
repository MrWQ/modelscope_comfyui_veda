## 2. 阻断级错误（开发前必须修正）

### 🔴 E1 · ModelScope 缓存可能翻倍，直接撑爆 100GB 持久盘
- **问题**：设计 §6/§9 把 `MODELSCOPE_CACHE` 指向 `<root>/.cache/modelscope`，同时把模型落到 `ComfyUI/models/`。`modelscope` 的 `download/snapshot_download` 在 `--local_dir` 时会先写缓存再 **hardlink/copy** 到目标。在 `/mnt/workspace`（NAS）上 hardlink 常因跨文件系统回退为 **copy**，于是 55GB 模型 = 缓存 55GB + 目标 55GB = **110GB > 100GB → 下载中途磁盘写满、整个安装失败**。
- **修正**：
  1. 磁盘预检（P0）**必须把缓存开销计入预算**，不能只看模型大小；
  2. 设 `MODELSCOPE_CACHE` 与 `PIP_CACHE_DIR` 均在安装根内（已有），但**下载校验通过后，清理冗余的 `.cache/modelscope`**（state 已按目标文件记录完成态，不影响续传判定）；或测试把 `MODELSCOPE_CACHE` 直接指向目标父目录使"缓存即目标"；
  3. 提供 `--keep-cache` 关闭清理（默认清理以保磁盘）；
  4. M3 实测确认 `/mnt/workspace` 上是否会复制，据此定默认策略。

### 🔴 E2 · 只装 Veda 节点 ≠ 能跑 MiniMax-H3（缺模型加载器）
- **问题**：Veda 是**加速器节点**（MODEL in→out 穿透），它不加载模型。要出片还需 MiniMax-H3 的**模型加载器**。文档 P3 只 clone `Veda-on-ComfyUI`，P5 只下权重，**从未安装/确认加载器**。若所 clone 的 ComfyUI 版本未内建 MiniMax-H3 原生支持，工作流会直接缺节点。
- **修正**：在 P3/P5 明确二选一并在 M2 验证：
  - 方案 A（优先）：依赖 **ComfyUI ≥0.38.0 原生 MiniMax-H3 支持**（官方 "Day-0 support"），在 P1 升级后**显式校验原生加载器节点存在**；
  - 方案 B：显式安装 `ComfyUI-MiniMaxH3`（或等效官方节点），与 Veda 一并纳入 state/源链管理。
  - 验收（P7）增加"加载器节点可见"一项。

### 🔴 E3 · `--local-code` 与"免重装"在魔搭上自相矛盾
- **问题**：设计 §6 规则7 把代码+venv 放本地盘以加速 NAS 启动。但魔搭实例 **`/root`、`/tmp`、本地盘非 `/mnt` 路径关机即清空**，把 venv 放本地盘 = 每次新实例都要重建 venv → **直接违背"新开实例无需重装"的核心目标**。
- **修正**：在魔搭（检测到 `/mnt/workspace`）环境下 **`--local-code` 强制默认 OFF**，所有内容（含 venv）必须落 `/mnt/workspace`。`--local-code` 仅作为 T2/T3（本地盘持久）的可选逃生舱。DoD 与 §7.2 默认值需同步修正。

### 🔴 E4 · P8 默认前台启动会卡死安装命令
- **问题**：设计"默认启动 ComfyUI"。若在 `install.sh` 里前台启动，进程不返回，用户终端被长期占用，且与"运行一条命令后交付"的体验冲突（尤其在 Notebook 终端里）。
- **修正**：P8 改为**后台启动**（`nohup ... > run/comfyui.log 2>&1 &`），随后轮询 `/object_info` 探测就绪（复用 P7 smoke 逻辑，超时只 WARN），就绪后打印访问 URL/端口；并提供 `run/start.sh|stop.sh|status.sh` 供后续管理。安装命令应可立即返回。

### 🔴 E5 · 源优先级在魔搭上含被墙的 hf-mirror
- **问题**：默认 `--source-priority modelscope,hfmirror,huggingface`。但 V2 表明**魔搭 Notebook 外网受限、含 huggingface**，hf-mirror 大概率不可达，白白浪费探测与超时。
- **修正**：源链**按环境自适应**（见优化 O2）：
  - 魔搭环境：`modelscope → github(gh-proxy) → github(codeload 末位)`，**不放入 hf-mirror/huggingface**；
  - 通用 Linux/Windows：`modelscope → hf-mirror → huggingface`；
  - 现状的固定链改为"环境探测 + 可覆盖 `--source-priority`"。

### 🔴 E6 · GitHub 兜底用 codeload 同样被墙
- **问题**：P1/P3 的"git clone 失败 → tarball 镜像解压"未指定镜像域名，注释写 `codeload/镜像站`。`codeload.github.com` 同属 GitHub，**魔搭外网受限下同样不可达**，兜底无效。
- **修正**：GitHub 类源统一走**可达代理**：
  - `git clone` 通过 `git config url."https://gh-proxy.com/https://github.com/".insteadOf ...`（仅本次会话/局部配置，用完还原，避免污染用户全局）；
  - tarball 用 `https://gh-proxy.com/https://github.com/<repo>/archive/<ref>.tar.gz`；
  - 代理域名做成**多候选列表 + 可达性探测**（gh-proxy.com / mirror.ghproxy.com / gitclone.com），任一失败切下一个；
  - 明确**禁止携带 Token/Cookie**（只读公开资源），写入安全设计。

## 3. 重要修正（🟡，非阻断但必须处理）

1. **默认 Profile 按实测 VRAM 选，而非假设 `env=modelscope → standard`**：P0 已探测 `nvidia-smi` 显存，应据此映射：<16GB→`lowvram`、16–24GB→`standard`、>24GB→`full`；`standard` 在 A10 24GB 的 VRAM 可行性仍是**假设 A1（F14）**，必须由 M4 实测定论，不通过则自动降级并回填默认档。
2. **锁文件 stale 清理**：`.setup.lock` 增加 **PID/心跳 stale 检测**——若持有者进程已死，自动释放，避免崩溃后永久死锁（E603 误报）。
3. **版本可复现**：ComfyUI 与 `Veda-on-ComfyUI` 在 manifest 中**锁定已知可用 commit/tag**，而非裸 `--depth 1` 拉 main（避免上游破坏性更新导致"昨天能装今天崩"）。
4. **smoke test 豁免与长超时**：首次启动需加载 55GB 模型，冷启动常 >180s。建议 P7 smoke 默认**仅做端口/节点就绪探测、不强制全模型加载**，超时只 WARN 并标注"首跑豁免，人工复核"；或超时放宽至 600s。
5. **License 地域限制提示**：P5 自动接受 License 时，日志与 README 增加一行：本许可**不适用于美国/欧盟/英国/韩国用户**，商业使用受限；中国用户个人非商业使用无碍。
6. **持久化路径自检强化**：P0 若检测到安装根不在 `/mnt/workspace`（魔搭环境）或落在 `/tmp`、`/root`、`/home` 等易失路径，**强烈 WARN 并建议 `--install-root /mnt/workspace/...`**（已有雏形，提升为显式拦截建议）。

## 4. 优化建议（🟢）

- **O1 一键 bootstrap 单行命令**：解决"脚本自身也需在持久盘"的鸡生蛋问题。提供形如 `curl -fsSL <稳定URL>/bootstrap.sh | bash`（URL 经 gh-proxy 可达）或 Notebook 终端直接粘贴的一行命令，自动把 `veda-setup/` 落到 `/mnt/workspace` 并执行 `install.sh`。免去"Web IDE 上传目录"摩擦，最贴合"人工只跑一条命令"。
- **O2 自适应源链（取代固定列表）**：P0 网络探测后生成《源可用性表》，按"环境 + 可达性"动态排序候选源，而非死用 `--source-priority` 默认值（与 E5 配套）。
- **O3 诊断包增强**：`--doctor` 包内增加：当前生效源链、各源延迟、egress 探测结论、`pip/modelscope` 版本、ComfyUI commit、Veda 节点 commit——便于远程排障。
- **O4 下载进度可视化**：大文件下载接入 `tqdm`/`ipywidgets` 进度条（Notebook 与终端均可用），避免长时间无输出的"卡死感"。
- **O5 启动即服务化**：`run/start.sh` 支持 `nohup` 后台 + 写 pid 文件 + `status.sh` 查健康；可选 `stop.sh`。安装完成即给出"如何启动/停止/查看日志"三行摘要。
- **O6 失败自愈提示分级**：终端末尾按错误码给出**唯一、可点击的下一步**（换 `--install-root` / 重试 / 提 issue 附诊断包），而非堆砌日志。

## 6. 优化后关键决策变更摘要（可直接回填 v2.3）

1. **磁盘预算**：把 `MODELSCOPE_CACHE` + `PIP_CACHE_DIR` 计入预检；下载校验后默认清理冗余 modelscope 缓存（新增 `--keep-cache`）。
2. **加载器**：P3 增加 MiniMax-H3 加载器（原生支持校验 或 显式安装节点），P7 增加"加载器节点可见"验收项。
3. **`--local-code`**：魔搭环境下强制 OFF（默认 ALL-ON-`/mnt/workspace`）；仅 T2/T3 可选。
4. **启动**：P8 后台启动 + 就绪探测 + `run/` 管理脚本；安装命令可立即返回。
5. **源链**：改为**环境自适应**（魔搭：`modelscope→github(gh-proxy)→codeload`；其他：`modelscope→hf-mirror→huggingface`）；GitHub 兜底统一走可达代理且多候选。
6. **锁**：增加 stale PID 检测与自动释放。
7. **可复现**：manifest 锁定 ComfyUI / Veda 节点 commit。
8. **License**：日志与 README 增加地域限制（US/EU/UK/SK 排除）提示。
9. **smoke**：首跑豁免全模型加载、超时放宽/仅 WARN。
10. **入口**：新增 bootstrap 单行命令（O1）。
