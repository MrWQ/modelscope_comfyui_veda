# Veda-on-ComfyUI 一键脚本 · 问题排错

出错时请先读本节「总体排错流程」，再按错误码或阶段定位。设计原理见 [设计文档](Veda一键脚本设计文档.md)，常规用法见 [使用说明](使用说明.md)。

---

## 1. 总体排错流程

任何失败都会**退出非 0 + 打印错误码 + 自动生成诊断包**。建议顺序：

1. **看错误码**：终端会打印 `失败：错误码 EXXX (code)` 与原因。
2. **看运行模式**：日志开头有 `MODE_DECISION` 事件（`install` / `launch-only`），确认本次走的是安装段还是仅启动——排错前先弄清路径。
3. **看日志**：`<root>/logs/setup_YYYYMMDD_HHMMSS.jsonl`（结构化，可全文检索阶段/步骤）。
4. **生成诊断包**（环境快照 + 配置 + state + 最近日志 + 文件树）：
   ```bash
   python setup_veda.py --doctor
   ```
   输出 `logs/diagnose_YYYYMMDD_HHMMSS.tar.gz`（Windows 为 `.zip`）。提 issue / 求助时附上此文件即可，无需手动收集。
5. **对照下文错误码表 / 阶段排错**定位根因。
6. 多数下载 / 网络类故障可**直接重跑**脚本——已完成资产按状态幂等跳过，不会重复下载。

> 日志不写日志目录以外的任何文件；诊断包仅在 `<root>/logs/` 内生成（设计文档 §12 约束）。

## 3. 按阶段排错

### P0 预检
- **E101/E102**：环境不满足（OS / GPU 算力 < SM80）。`nvidia-smi` 验证显卡；纯 CPU 无法运行；Veda 节点默认 Triton INT8 后端需 SM80+（A10/A100/30-40 系）。**E102（算力不足）自 v2.3.10 起不再是致命错误**：自动档检测到 GPU 但算力 < SM80 改为交互询问是否继续（默认不继续），`--yes` 直接继续，用户拒绝为干净退出（返回 0）。**E103（无 GPU）自 v2.3.9 起不再是致命错误**：自动档未检测到 NVIDIA GPU 时改为交互询问是否继续（默认不继续），`--yes` 直接继续，用户拒绝为干净退出（返回 0）而非 E103，无需再为此报错。
- **E104**：持久盘空间不足。脚本会尝试**自动降档**（`full→standard→lowvram`）；仍不足则报错。清理 `/mnt/workspace` 无用文件，或用 `--skip-models` / `--profile minimal` 先搭环境。
- **E105/E602**：安装根不可写。`--install-root` 指定可写目录（魔搭务必落在 `/mnt/workspace` 下）。
- **E106**：所有下载源不可达。先在魔搭实例跑 `--doctor` 看 `network_probe` 结果（见 §4）。
- **E601**：`<root>/ComfyUI` 已存在且非本脚本建立。换根目录或确认无误后 `--force`。
- **E603**：见 §7。

### P1 ComfyUI 本体
- **E201**：git 直连 / 代理 / tarball 全部失败。几乎都是**网络**（GitHub 被墙 / 代理不可达）。看日志里 `P1/repo` 各候选错误；确认 `gh-proxy.com` 可达（§4）。可重试，脚本会自动换下一个代理候选。
- **E202**：版本过低。锁定 commit（`7f7fd918…`）应满足 ≥0.38.0；若被本地篡改，删 `ComfyUI/.git` 让脚本重装。

### P2 依赖 / venv
- **E203/E204**：pip / venv 失败。日志含 pip stderr。可删除 `<root>/venv` 让脚本重建（脚本已内置「重建 venv 并重装」兜底）。魔搭环境复用镜像 `torch`（`--system-site-packages`），无需重新下载 torch。

### P3 Veda 节点
- **E301**：Veda 节点安装失败。同 P1 网络思路（代理候选 + tarball 兜底）。Veda 节点锁定 commit `67e4eb55…`。
- FA4 后端为 **best-effort 可选增强**（`install_fa4.py` 自测失败不阻断）；默认 Triton INT8 后端即可工作。

### P4 / P5 模型资产
- **E401**：所有源失败。魔搭内源链为 `modelscope → hf-mirror（实测可达，优先兜底）→ gh-proxy 代理 HF（末位 best-effort）`；通用环境 `modelscope → hf-mirror（可达时）→ huggingface 直连（末位，v2.3.8 补齐）`。源不可达见 §4。**重跑可断点续传**（已下文件按状态跳过）。
  - **历史案例（v2.3.7 已修复）**：2026-10-12 魔搭 A10 实例上 `veda-predictor-t2va` 报 E401——根因是旧版把 Veda 预测器（仓库根裸文件名）下载到 `models/` 根目录而校验目标在 `models/veda/` 子目录，**下载成功却落错位置**；且 hf 兜底被错误指向 gh-proxy 端点（不代理 HF）。修复后：落点按源类型分派、hf 兜底走 hf-mirror，且检测到旧版错位文件会**自动迁移回收**（日志出现 `回收错位文件` 即命中，不重新下载）。
- **E402**：校验失败（大小低于 `min_bytes` 或 safetensors 头部不可解析）。通常是下到 HTML 错误页/截断。删除对应文件后重跑。
- **E403**：License 未接受。交互模式需人工确认；非交互模式去掉 `--no-accept-license`。

### P7 验收
- **E501**：版本或资产缺失。确认前面阶段完成，重跑补齐（幂等）。
- **E502**：`torch.cuda` / `triton` 不可用。确认 GPU 驱动与 venv 依赖；Windows 会自动试装 `triton-windows`。
- **E503**：`/object_info` 未探测到 Veda / 原生加载器节点。**若启用 `--smoke-test`，首跑因需加载 ~42GB 模型常 >180s，超时放宽至 600s，超时/失败仅记 WARN（错误码 E503）并标注「首跑豁免/待人工复核」，不阻断整体验收结论**。未启用 smoke 时，P7 仍会报告节点目录与 torch 状态。

### P8 启动
- **重复执行命令后进程行为（v2.3.8 起安全）**：P8 与 `run/start.sh` 均内置「已运行守护」——探测到 8188 已就绪即**跳过启动**（日志 `P8/skip` / 脚本输出 `already running`），不会二次拉起实例。旧版本无此守护：若你的 `run/comfyui.log` 出现 `Address already in use` / 端口绑定失败，说明起过第二个实例——`run/stop.sh`（或 `kill $(cat run/comfyui.pid)`）清理多余进程后重跑即可（v2.3.8+ 不会复现）。
- **终端关闭后 ComfyUI 消失（v2.3.8 已修复）**：旧版安装期首启未脱离控制组，魔搭 Web IDE 终端关闭（SIGHUP）会杀死 ComfyUI；v2.3.8 起 POSIX 用 `start_new_session=True`，不受影响。旧环境升级后重跑一次安装/启动即可。
- **Windows 停不掉（v2.3.8 已修复）**：旧 `stop.bat` 的 `taskkill /FI WINDOWTITLE` 匹配不到无窗口的 python.exe；v2.3.8 起 `stop.bat` 用 PowerShell 按 `CommandLine` 匹配 `main.py` 精确停止。重跑安装/启动会重新生成 `run/*.bat`。
- **端口未开放却报"完成"（v2.3.11 已修复）**：旧版在 120s 就绪探测超时后仅 WARN 仍打印"启动完成"与可访问 URL，且启动子进程句柄被丢弃，真实崩溃（CUDA/OOM）被埋进 `run/comfyui.log` 无人可见。v2.3.11 起：进程已退出则抛 **E701** 并就地打印 `run/comfyui.log` 末尾 50 行（顶层输出"失败：E701"+诊断包）；进程存活但超时则诚实标记"未就绪"（`final_summary` 不再宣称可访问，提示 `run/status.sh` 复查）。若 `run/status.sh` 仍 `DOWN`：先 `cat run/comfyui.log` 看崩溃栈；确认 `nvidia-smi` 正常、venv 内 `torch.cuda.is_available()` 为 True；大模型首载 >120s 属正常，等后用 `run/status.sh` 复查即可。
- **未启动却显示可访问 URL（v2.3.12 已修复）**：旧版在"根本未启动"的运行（`--no-launch` / 仅 `--only` 安装环节未含 p8 / `--mode launch --no-launch`）下，`final_summary` 仍落入"一键搭建完成"分支并打印 `http://127.0.0.1:8188` 可访问 URL（实际无服务在跑）。v2.3.12 起改为三态：`launch_ready=True`（已就绪）→ 带 access 字段；`False`（已启动未就绪）→ 诚实提示；`None`（本次未启动）→ 明确"未启动 ComfyUI"并指引 `run/start.sh`，**绝不输出 false access**。
- **模型下载"不完整却判定成功"（v2.3.12 已修复）**：所有资产均为 `.safetensors`，校验原本只看头部 JSON，头部合法但**数据段被截断**（下载中断、文件大小仍 ≥ min_bytes）会记为 `ok`，造成"下载不完整却判定成功"。v2.3.12 起 `verify_safetensors_header` 额外按张量 `data_offsets` 校验 `8 + 头长 + 数据段长 == 实际文件大小`，截断即判失败并转下一流源/报 E401；并新增"完整文件已存在但 state 未记录"的免重下恢复，以及每次重试前清理残留半截文件。若遇某资产反复 E401，用 `python setup_veda.py --doctor` 取诊断包，并核对 `run/` 日志中该资产的 `校验失败/源失败` 详情。
- **启动报 `AttributeError: module 'torch.library' has no attribute 'custom_op'`（v2.3.13 起早暴露）**：`comfy_kitchen`（ComfyUI 的 `comfy/quant_ops.py` 引入）需要 `torch.library.custom_op`，该 API 自 **torch>=2.0** 才有。魔搭环境 venv 用 `system_site_packages` **复用镜像自带 torch**（脚本不自行安装 torch），若镜像 torch < 2.0 就会在 import 阶段崩。v2.3.13 起 `preflight_launch` 在启动前即探测并直接报 **E701**，原因形如"torch 版本过低（1.13.1），缺少 torch.library.custom_op（comfy_kitchen 依赖，需 torch>=2.0）；魔搭环境请选用 torch>=2.0 的 GPU 镜像"——遇到即**换用 torch>=2.0 且带 CUDA 的 GPU 镜像**（多数魔搭 GPU 镜像默认 torch 2.1+，已含 `custom_op`）。复现诊断：`/mnt/workspace/comfyui-veda/venv/bin/python -c "import torch; print(torch.__version__); print(hasattr(torch.library,'custom_op'))"`，输出 `no_custom_op` 即命中。

## 4. 网络相关排错

脚本在 P0 探测以下主机（`lib/platform.py` 的 `DEFAULT_HOSTS`）：
`modelscope.cn` / `hf-mirror.com` / `huggingface.co` / `github.com` / `gh-proxy.com` / `gitclone.com`。

- **魔搭实例内 huggingface 受限（设计文档 F17/E5）**：正常现象。源链自动排除 `hf-mirror` / `huggingface`，改走 `modelscope → github(gh-proxy) → codeload`。无需处理。
- **GitHub 不可达（E201）**：确认 `gh-proxy.com` / `ghproxy.net` / `gitclone.com` 可达。脚本按候选链依次尝试，全部失败才报 E201。可手动验证：
  ```bash
  curl -fsSL -o /dev/null -w "%{http_code}\n" https://gh-proxy.com/https://github.com/comfyanonymous/ComfyUI
  ```
- **代理全不可达**：可能处于完全隔离网络。至少保证 `modelscope.cn` 可达（模型主源）。GitHub 兜底仅用于 ComfyUI/Veda 本体，缺失则无法安装本体（可手动把仓库放到对应目录后重跑，脚本会跳过已存在项）。
- **模型下载慢 / 中断（E401）**：免费额度可能中途耗尽。脚本支持随时中断、重跑续传（`modelscope` / `hf` CLI 均支持断点）；已落盘文件不重下。

## 5. 磁盘 / 缓存排错

- **E104 或安装中途「No space left on device」**：
  - 魔搭持久盘 `/mnt/workspace` 需 ≥ 约 **46GB**（`standard` 档：模型 ~42GB + ComfyUI/venv ~3–4GB）。
  - 缓存默认重定向到**本地盘** `/root/.cache/modelscope`（与 `/root/.cache/huggingface`、`/root/.cache/pip`），**不占用持久盘**，规避峰值爆盘（设计文档 E1）。
  - 若持久盘不足，脚本自动降档；仍不足可：清理无用文件 / `--skip-models` 先搭环境 / `--profile minimal`。
- **`--keep-cache`**：默认下载后清理缓存省磁盘。仅在需要保留以便二次部署时加此参数。

## 6. GPU / 显存排错

- **E102（v2.3.10 变更）**：GPU 已检测但算力 < SM80（非 NVIDIA 或老卡）。Veda 节点默认 Triton INT8 后端需 SM80+。**自动档检测到低算力 GPU 不再直接退出**，而是交互询问是否继续（默认不继续）；确认继续请回答 `y` 或加 `--yes`。此前 `compute_cap_ok` 为死代码、E102 从未触发，v2.3.10 已修正为可询问。
- **无 GPU（v2.3.9 变更）**：自动档未检测到 NVIDIA GPU **不再直接退出**，而是交互询问是否继续（默认不继续）；确认继续请回答 `y` 或加 `--yes`，将沿用 `standard` 档安装（仅准备环境/预下载，运行时仍需 GPU）。显式 `--profile X` 跳过询问。非交互环境未加 `--yes` 会打印说明后干净退出（返回 0）。
- **E601（v2.3.10 变更）**：安装根已存在非本脚本建立的 ComfyUI（无 `.git`）。**不再直接退出**，而是交互询问是否覆盖继续（默认不继续）；`--yes` 或 `--force` 直接继续。`--force` 专用于覆盖外来 ComfyUI 检测，等效于自动确认该询问。
- **自动降档**：`auto` 档位下，VRAM <16GB→`lowvram`（需 `--accept-third-party`），16–24GB→`standard`，>24GB→`full`。磁盘不足时也会触发降档。
- **显存不足出图 OOM**：选更低档位，或减小分辨率/帧数；`lowvram` 档走第三方量化权重（需 `--accept-third-party`）。
- **E502（triton 不可用）**：确认 venv 内 `torch`/`triton` 可导入；Windows 下脚本自动尝试 `triton-windows`（安装失败会自动回滚，不影响主流程）。

## 7. 并发锁冲突（E603）手动释放

脚本用 `<root>/.setup.lock` 防止并发安装。正常结束会自动释放；崩溃残留的锁带 **stale PID 检测**（进程已死则自动释放）。若仍报 E603：

```bash
# 确认没有其他安装进程在跑后：
rm -f /mnt/workspace/comfyui-veda/.setup.lock   # 路径按你的 --install-root 调整
```
再重跑脚本。

## 8. 模型校验失败（E402）

`min_bytes` 是真实文件大小的安全下界（已按魔搭官方清单校准，非估算）。出现 E402 通常是：
- 下到 HTML 错误页 / 登录页（网络中间页）；
- 文件被截断。

处置：删除该 safetensors 文件（位于 `<root>/ComfyUI/models/...`），重跑脚本重新下载并校验。可用 `--deep-verify` 做全量哈希校验。

## 9. 诊断包内容（提 issue 用）

`diagnose_*.tar.gz/.zip` 含：
- `env_snapshot.txt`：`uname`、`python --version`、`nvidia-smi`、`pip freeze`、`df -h`；
- `network_probe.json`：各下载源可达性；
- `config.json`：本次 profile / 根目录 / 是否魔搭；
- `setup-state.json`：幂等状态；
- `recent_log.txt`：最近约 2000 行结构化日志；
- `file_tree.txt`：安装根文件树（跳过 `.git`/`.cache`/`venv` 细节）；
- `comfyui_run_log_tail.txt`：若已启动，附 ComfyUI 运行日志尾部 500 行。

## 10. 已知限制 / 待实测（G4–G7）

以下为运行期探测项，设计已做自适应兜底，但建议在真实魔搭实例上验证：

- **G4** `modelscope download --local_dir` 在 `/mnt/workspace` 是否复制缓存（影响 E1 缓存预算）；
- **G5** 魔搭内 `gh-proxy.com` / `gitclone.com` 是否可达（影响 GitHub 兜底）；
- **G6** A10 24GB 实测能否跑 `standard` 档（决定默认档位）；
- **G7** 魔搭本地盘（`/root`）容量是否 ≥ 最大模型体积（决定缓存重定向策略）。

如你在魔搭实例上遇到与上述相关的异常，请附诊断包反馈，便于进一步校准默认值。
