# 2026-10-16 工作记录

## v2.3.15：P2 venv 创建健壮性 + 非 CUDA 后端（AMD ROCm）识别

**触发**：用户贴新实例（dsw-2262705）`bash veda-setup/install.sh` 日志——全新实例走 install 路径，P2 建 venv 时 `python3 -m venv --system-site-packages` 退出码 1，脚本崩溃为 `FATAL/unexpected` 且丢失真实报错（仅留 `[Errno 2] No such file or directory: '.../venv/bin/python3'` 二次症状）。诊断包 env_snapshot 显示：Python 3.12.13 自定义构建、Debian 风格 `dist-packages`、pip 26.2.1、torch 2.12.0（**ROCm/AMD 镜像**：`vllm+rocm723`/`amd-aiter`/`amd-quark`/`nixl-rocm`、`nvidia-smi not found`）；`install_completed=false`、`is_installed=false`。

**根因**：`platform.ensure_venv` 用 `subprocess.run(..., check=True)`，部分魔搭/自定义镜像因 `ensurepip` 不可用（缺 `python3-venv` 或未捆绑引导轮）使 `venv` 失败；原始 `CalledProcessError` 被顶层 `except Exception` 吞成无意义 `FATAL/unexpected`，真实 stderr 丢失。

**修复**（`lib/platform.py` + `lib/phases.py`）：
1. `ensure_venv` 三级尝试 + 捕获真实 stderr + 永不抛错：标准 venv → `--without-pip`（绕过 ensurepip）→ 回退系统 Python（`sys.executable`，本就 `--system-site-packages`），回退置 `ctx.venv_fallback=True` 并 WARN 带 `last_err`。
2. `phase2_deps`：当 `venv_fallback` 时跳过 `requirements.txt` 安装（保护镜像预置系统环境，如 ROCm torch）。
3. `_launch_precheck`：新增 `torch.version.hip` 探测，ROCm 等"非 CUDA 后端"诚实跳过启动，提示换 NVIDIA CUDA 镜像（避免误判 `torch.cuda.is_available()=True` 后加载 nvfp4 崩溃）。
4. `Ctx` 新增 `venv_fallback` 字段。

**校验**：py_compile 全过；自测新增 [13] ensure_venv 回退链三场景 + [14] phase2_deps fallback 跳过 requirements / 正常路径仍安装 + `_launch_precheck` ROCm 判定，测试总 **67 项全绿**。

**文档**：设计文档 / 使用说明 / 问题排错 / README / `setup_veda.py` docstring 升 v2.3.15（版本行 + 状态行 + 修订记录表新增 v2.3.15 条目）。

**关键结论**：此实例是 **AMD ROCm 镜像而非 NVIDIA CUDA**，Veda 依赖 NVIDIA 专属能力（nvfp4），即便修好 venv 也跑不了——用户应换 NVIDIA CUDA 镜像。脚本侧做到"不崩溃、诚实拦截并指引"。
