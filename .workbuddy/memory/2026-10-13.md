## v2.3.12：同类"谎报/不完整"缺陷复查修复（用户点名：下载不完整、启动不完整、超时不规范）
- 触发：用户在 v2.3.11 后要求"自检项目，有没有类似 bug：如下载不完整、启动不完整、超时处理不规范"。
- 普查结论（三类）：
  1. **启动不完整/谎报（同 P8 类）**：`final_summary` 仅区分 `launch_ready=False`；当 `launch_ready=None`（本次根本未启动：`--no-launch` / 仅 `--only` 安装环节 / `--mode launch --no-launch`）会落入"一键搭建完成"分支并打印 `http://127.0.0.1:8188` **假可访问 URL**（实际无服务）。
  2. **下载不完整却判定成功**：所有资产均为 `.safetensors`；`verify_safetensors_header` 旧版**只校验头部 JSON**，头部合法但数据段被截断（下载中断、文件大小仍 ≥ min_bytes）仍记为 `ok`。截断文件尺寸仍可能 ≥ min_bytes，故仅靠 size 下界拦不住。
  3. **超时/残留**：下载源失败后残留半截 `target` 未被清理，存在"CLI 续传损坏文件"或"误把残留当已下载校验通过"风险；损坏（HEAD 读不出）的 `.git` 只会靠 tarball 兜底 `rmtree`，不主动重建。
- 修复（`lib/phases.py` + `lib/assets.py`）：
  - `final_summary` 三态化：`True`→带 access；`False`→诚实未就绪 WARN；`None`→明确"未启动 ComfyUI"指引 `run/start.sh`，**绝不输出 false access**。
  - `verify_safetensors_header` 增强：按张量 `data_offsets` 最大值要求 `8 + 头长 + 数据段长 == 实际文件大小`，截断即判失败。
  - `download_model_asset`：新增"完整文件已存在但 state 未记录"（上一轮下载成功却在写 state 前中断）免重下直接复用；每次源尝试前 `os.remove` 残留半截 `target`。
  - `_git_clone`：`.git` 存在但 `rev-parse HEAD` 读不出（克隆/检出中断）时 `rmtree` 后重新获取。
  - 下载超时本身已规范（subprocess `timeout=1800`，超时抛 E401 经所有源失败，非静默），仅补清理即可。
- 文档：`设计文档`（版本行/状态行/修订记录 v2.3.12）、`问题排错`（P8 段补"未启动谎报""下载不完整"两条 v2.3.12 说明）、`使用说明`+`README` 版本引用、`setup_veda.py` docstring 版本。
- 校验：py_compile 全过；`test_v2310.py` 增至 **43 项全绿**——新增 [8] safetensors 数据段完整性（合法/截断/坏头）、[9] download 回收+清理（恢复完整文件 / 残次清理后二源成功）、[10] final_summary 三态（None 无 access / True 有 access / False warn）。

## v2.3.13：torch 运行时不兼容早暴露（用户实测 `git pull` 后重跑触发新根因）
- 触发：用户 `git pull`（含 v2.3.11/2.3.12 修复）后跑 `bash veda-setup/install.sh`，脚本**正确地**捕获崩溃、打印 `run/comfyui.log` 尾部、报 E701（v2.3.11 诚实化生效 ✅）。但日志暴露新真实根因：`AttributeError: module 'torch.library' has no attribute 'custom_op'`（comfy_kitchen 的 `comfy/quant_ops.py` 引入，需 `torch.library.custom_op`，自 torch>=2.0 才有）。
- 根因：魔搭环境 venv 用 `system_site_packages=True`（`phases.py` P0 `ctx.system_site_packages = is_ms`）**复用镜像自带 torch**，脚本不自行安装 torch；该镜像 torch < 2.0 → 缺 `custom_op` → import 阶段即崩。与"无 GPU"是两个独立问题（WARN 已报无 GPU；但 `custom_op` 崩在 GPU 判断之前）。
- 修复（`lib/phases.py`）：
  - 新增 `_torch_compat_ok(venv_python)` 探针：执行 `import torch; print(__version__); print('custom_op' if hasattr(torch.library,'custom_op') else 'no_custom_op')`；解析用**精确整行匹配**（避免 `no_custom_op` 子串误判 `custom_op`）；返回 `(ok, detail)`。
  - `preflight_launch` 启动前调用：torch 不兼容即 `raise PhaseError(701, "torch 运行时不兼容，无法启动 ComfyUI：{detail}")`，顶层输出"失败：E701"+诊断包，给出可操作原因（"魔搭环境请选用 torch>=2.0 的 GPU 镜像"），而非崩溃后 dump 原始 traceback。
  - `phase7_verify` 同步探测（仅 `log.warn`，与"无 CUDA"同级不硬阻断），明确预警"torch 运行时不兼容，ComfyUI 启动将失败"。
- 文档：`设计文档`（版本行/状态行/修订记录 v2.3.13）、`问题排错` P8 段补"custom_op"排错条、`使用说明`+`README`+`setup_veda.py` 版本引用。
- 校验：py_compile 全过；`test_v2310.py` 增至 **46 项全绿**——新增 `test_torch_compat`（torch 2.1.0→ok / 1.13.1→too_old 含"torch>=2.0" / import 失败→"torch 无法导入"）。
- 给用户的结论：v2.3.11 诚实化已验证；新崩是镜像 torch<2.0，换 torch>=2.0 的 GPU 镜像即可（且本容器无 GPU，Veda 本就无法运行，必须换 GPU 实例）。
